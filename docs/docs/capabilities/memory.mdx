# Memory

## Overview

Memory is Lightflare's long-term context layer. It lets agents remember useful information beyond a single prompt and lets users manage that information directly.

Memory supports multiple sources:

- Manual memories added from the Memories page.
- Memories created from chat history.
- Uploaded files, where the file metadata and extracted text become searchable context.
- System or assistant-generated summaries when conversation context needs to be compacted.

Memory also supports different visibility scopes:

- User-scoped memory is private to one user.
- Session-scoped memory is tied to a specific chat session.
- Global or shared memory can be used as broader context when available.

Uploaded documents are handled as memory too, but the document content is split into smaller searchable chunks. This lets a large PDF or text file be retrieved by the specific sections that match the current question instead of forcing the whole file into the prompt.

At a high level, retrieval works like this:

1. The current user message is used as the search query.
2. Lightflare searches normal memories and document chunks that the user is allowed to access.
3. Semantic search finds conceptually related content.
4. Full-text search helps with exact names, IDs, filenames, code terms, and phrases.
5. Results are scored with configurable weights for semantic match, text match, recency, and scope.
6. The best results are added to the agent's context with enough metadata to explain where the information came from.

The Memories page uses the same retrieval behavior when searching. When there is no search query, it behaves like a normal list and can sort by creation time.

## Properties

| Variable | Default | Description |
| --- | --- | --- |
| `LIGHTFLARE_MEMORY_UPLOAD_DIR` | `/tmp/lightflare/memory-uploads` | File upload directory for memory attachments. |
| `LIGHTFLARE_MEMORY_COMPACTION_TOKEN_THRESHOLD` | `3000` | Token threshold for memory compaction. |
| `LIGHTFLARE_MEMORY_COMPACTION_BATCH_SIZE` | `5` | Memory compaction batch size. |
| `LIGHTFLARE_MEMORY_SESSION_MEMORY_LIMIT` | `50` | Session memory limit. |
| `LIGHTFLARE_MEMORY_SIMILARITY_RESULT_LIMIT` | `10` | Similarity search result limit. |
| `LIGHTFLARE_MEMORY_EMBEDDING_EXECUTOR_CORE_POOL_SIZE` | `2` | Embedding executor core pool size. |
| `LIGHTFLARE_MEMORY_EMBEDDING_EXECUTOR_MAX_POOL_SIZE` | `4` | Embedding executor max pool size. |
| `LIGHTFLARE_MEMORY_EMBEDDING_EXECUTOR_QUEUE_CAPACITY` | `100` | Embedding executor queue capacity. |
| `LIGHTFLARE_CONTEXT_SEARCH_MIN_CANDIDATE_LIMIT` | `20` | Minimum candidate rows loaded per context search source before ranking. |
| `LIGHTFLARE_CONTEXT_SEARCH_CANDIDATE_LIMIT_MULTIPLIER` | `4` | Multiplier applied to the requested result limit when loading search candidates. |
| `LIGHTFLARE_CONTEXT_SEARCH_MAX_CHUNKS_PER_DOCUMENT` | `2` | Maximum document chunks from a single document after ranking. |
| `LIGHTFLARE_CONTEXT_SEARCH_MEMORY_PAGE_SEARCH_LIMIT` | `500` | Maximum relevance-ranked memory IDs considered for Memories page search pagination. |
| `LIGHTFLARE_CONTEXT_SEARCH_VECTOR_WEIGHT` | `0.55` | Vector rank contribution to context search score. |
| `LIGHTFLARE_CONTEXT_SEARCH_TEXT_WEIGHT` | `0.30` | Full-text rank contribution to context search score. |
| `LIGHTFLARE_CONTEXT_SEARCH_RECENCY_WEIGHT` | `0.10` | Recency contribution to context search score. |
| `LIGHTFLARE_CONTEXT_SEARCH_SCOPE_WEIGHT` | `0.05` | Scope boost contribution to context search score. |
